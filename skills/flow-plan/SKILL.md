# Flow Plan

ユーザーから実装要件をヒアリングし、詳細な実装計画を `./flow/plan/<YYYYMMDDHHmm>_plan.md` に保存する。

## Workflow

### Step 1: ヒアリング

AskUserQuestion を使って以下の3カテゴリを順に聞き出す。一度に多くの質問をしない（最大2問ずつ）。

**1. 目的・背景**
- 何を実装したいか
- なぜこの実装が必要か（ビジネス上の背景）

**2. 技術的制約**
- 使用言語・フレームワーク
- 既存コードの構成・制約
- 依存ライブラリの指定

**3. スコープ・優先度**
- どこまでやるか（MVP or フル実装）
- 優先する機能・後回しにする機能

各回答を得たら、計画ファイルの「ヒアリング記録」セクションに質問と回答を随時記録する。

### Step 2: コードベース調査

ヒアリング内容に基づき、関連する既存コードを調査する：

1. Glob/Grep で対象ファイル・関数を特定
2. 影響範囲を把握（依存関係、呼び出し元）
3. 既存のパターン・規約を確認

### Step 3: 実装計画の作成

以下の3セクションを含む計画を作成する：

#### 3-1. ファイル変更リスト

| 操作 | ファイルパス | 変更概要 |
|------|-------------|---------|
| 新規 | src/xxx.ts | 〜の実装 |
| 修正 | src/yyy.ts | 〜の追加 |
| 削除 | src/zzz.ts | 不要になったため |

#### 3-2. 関数/メソッド設計

各ファイルで追加・変更する関数を以下の形式で記述：

```
## <ファイルパス>

### <関数名>(引数): 戻り値
- 責務: 〜
- 処理概要:
  1. 〜
  2. 〜
- 呼び出し元: 〜
- 依存: 〜
```

#### 3-3. タスク分割

実装順序を考慮し、依存関係に基づいてステップに分割する：

```
## タスク一覧

### Step 1: <タスク名>
- 対象ファイル: 〜
- 作業内容: 〜
- 完了条件: 〜

### Step 2: <タスク名>
...
```

### Step 4: 計画ファイルの保存

`./flow/plan/` ディレクトリに `<YYYYMMDDHHmm>_plan.md` 形式で保存する。
日時はファイル作成時点の現在時刻を使用する（例: `202603301430_plan.md`）。

ファイル構成：

```markdown
# 実装計画: <タイトル>

作成日時: YYYY-MM-DD HH:mm

## ヒアリング記録

### 目的・背景
Q: ...
A: ...

### 技術的制約
Q: ...
A: ...

### スコープ・優先度
Q: ...
A: ...

## ファイル変更リスト

| 操作 | ファイルパス | 変更概要 |
|------|-------------|---------|
| ... | ... | ... |

## 関数/メソッド設計

### <ファイルパス>
...

## タスク分割

### Step 1: ...
...
```

### Step 5: ユーザーレビュー

計画ファイルの保存後、ユーザーにレビューを依頼する：

1. 計画の概要を表示する
2. AskUserQuestion で承認・修正を確認する
3. 修正指示があれば計画を更新し、再度レビューを依頼する
4. 承認されたら計画ファイルのステータスを「承認済み」に更新する
