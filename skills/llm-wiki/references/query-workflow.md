# Query ワークフロー

wikiを検索して質問に回答する手順。

## Step 1: 質問を解析する

ユーザーの質問から以下を特定:

- キーエンティティ（人名、組織名、ツール名）
- キーコンセプト（技術、手法、テーマ）
- 質問の種類:
  - **事実確認**: 特定の情報を探す
  - **比較**: 2つ以上の対象を比較する
  - **統合**: 複数の情報を横断して考察する
  - **探索**: オープンエンドな調査

## Step 2: wikiを検索する

1. `wiki/index.md` を読み込み、関連するページを特定する
2. キーワードで `wiki/` 内を Grep 検索し、追加の関連ページを見つける
3. 関連ページを読み込む（source-summary, entity, concept, comparison, synthesis）
4. 必要に応じて、リンク先のページも辿って読む

検索順序:
- まずインデックスのカテゴリ名とページ説明でスキャン
- 次にGrepでwikiページ内のキーワードを検索
- 最後に関連ページの「関連項目」セクションを辿る

## Step 3: 回答を合成する

- wiki内のページを引用しながら回答を構成する
- 出典は `[[page-name]]` リンクで明示する
- 情報が不完全な場合、何が不足しているか明記し、取り込むべきソースを提案する
- ソース間で矛盾がある場合、両方の見解を出典付きで提示する

回答形式はユーザーの質問に応じて柔軟に:
- 事実確認 → 簡潔な回答 + 出典
- 比較 → 比較表 + 分析
- 統合 → 構造化された考察
- 探索 → 関連ページの案内 + 知見のまとめ

## Step 4: wikiページとして保存を提案

以下の場合、回答をwikiページとして保存することを提案する:

- 複数ソースを横断した新しい統合的考察がある場合 → `synthesis-{topic}.md`
- 比較分析を行った場合 → `comparison-{topic}.md`
- ユーザーが明示的に保存を希望した場合

保存する場合:
1. 適切なページ種別とファイル名を決定
2. テンプレートに従ってページを作成
3. `wiki/index.md` を更新
4. `wiki/log.md` に追記: `## [YYYY-MM-DD] query | "質問内容"`

## 回答不能な場合

wikiに関連情報がない場合:
1. その旨を明確にユーザーに伝える
2. 回答に必要と思われるソースの種類を提案する
3. 必要に応じてスタブページ（後で埋めるための空ページ）の作成を提案する
