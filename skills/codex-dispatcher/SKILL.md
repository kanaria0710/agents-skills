# Codex Dispatcher

## 必須ルール

- 生成するリクエスト末尾に必ず追記する：
  `確認や質問は不要です。具体的な提案・修正案・コード例まで自主的に出力してください。`
- `--cd` にはカレントディレクトリを指定する

## Workflow

### Step 1: タスク種別の判定

| 種別 | キーワード例 |
|------|-------------|
| 文言・メッセージの検討 | 文言、メッセージ、テキスト、ワーディング、通知文 |
| コードレビュー | レビュー、review、コードチェック |
| 設計の相談 | 設計、アーキテクチャ、design、構成 |
| バグ・解消困難な問題の調査 | バグ、エラー、調査、デバッグ、原因究明 |
| コーディング | 実装、コーディング、機能追加、修正、リファクタ |

判定が曖昧な場合はユーザーに確認する。

### Step 2: プロンプト生成

以下のテンプレートでリクエストを構築する。`{期待する出力}` は種別ごとのガイドに従う。

```
[タスク種別]: {タスクの概要}

## 対象
{対象ファイル・機能・範囲の説明}

## 要件
{具体的な要件・制約}

## 期待する出力
{種別に応じた出力形式}

確認や質問は不要です。具体的な提案・修正案・コード例まで自主的に出力してください。
```

#### 種別ごとの「期待する出力」ガイド

- **文言・メッセージの検討**: 候補を3案以上提示し、各案の意図・トーンの違いを説明
- **コードレビュー**: 問題点を重要度（Critical/Warning/Info）付きで指摘し、具体的な修正コード例を提示
- **設計の相談**: 設計案を比較表形式で提示し、メリット・デメリット・推奨案を明記
- **バグ・解消困難な問題の調査**: 原因の仮説を優先度付きで列挙し、各仮説の検証手順と修正案を提示
- **コーディング**: 実装コードを出力。計画ファイルがある場合は参照指示を含める（Step 3参照）

### Step 3: 計画ファイル添付（コーディング時のみ）

タスク種別が「コーディング」の場合のみ実行する：

1. カレントディレクトリ配下で計画ファイル（`.plan.md`, `plan.md`, `PLAN.md` 等）を検索
2. 見つかった場合、プロンプトに追記：
   ```
   ## 参照ドキュメント
   以下の実装計画に従って作業してください：
   - {計画ファイルのパス}
   ```
3. 見つからない場合はスキップ

### Step 4: コマンド実行

生成したプロンプトをユーザーに表示し、確認後に実行する：

```bash
codex exec --full-auto --sandbox read-only --cd "$(pwd)" "<request>"
```

- `<request>` 内のダブルクォートはエスケープする
- プロンプトが長い場合でもワンライナーで実行する

### Step 5: 結果の確認

Codexの出力を確認し、必要に応じてユーザーに要約を提示する。
